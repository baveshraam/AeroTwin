2) ZERO-LABEL ANOMALY DETECTION — NEW: src/l0_detect/anomaly.py
   This closes out the one item marked "scoped but not coded" in the prior
   session's plan (docs/ACTION_PLAN.md item 4). Implements a real PatchCore
   detector (Roth et al. 2022 recipe):
     - Frozen pretrained ResNet-18 backbone (torchvision), mid-level feature
       maps (layer2+layer3) concatenated into a patch grid — no fine-tuning.
     - fit(normal_images): builds a greedy k-center CORESET memory bank from
       NORMAL-ONLY images (zero defect labels needed) — this is the aerospace
       label-scarcity answer: flags damage types the supervised detector was
       never trained on.
     - Threshold calibration bug caught and fixed: initially calibrated on the
       same images used to build the bank (near-zero in-bank distance -> way
       too low a threshold -> 5/5 false alarms on held-out normals). Fixed by
       holding out a validation split of normal images NOT included in the
       bank and calibrating on those instead.
     - score(image): kNN distance from each test patch to the nearest bank
       patch -> anomaly score + a localisation heat-map (where the structure
       looks wrong).
     - _coreset() made memory-frugal (block-wise distance computation) after
       an OOM on this machine when a concurrent training job was also running.
     - Self-check (python -m src.l0_detect.anomaly) result after the fix:
         normal test scores  ~1.2 mean
         damaged test scores ~3.9 mean
         damage flagged: 5/5, false alarms: 0/5
     - Wired into src/pipeline.py: on --real (non-mock) runs with an image
       path, if a fitted bank exists at models/weights/anomaly_bank.npz, the
       pipeline also runs the anomaly branch and prints [L0b] ANOMALY/nominal
       alongside the supervised detector's [L0] line. Returns "anomaly" key
       in run_scan()'s result dict.
     - train_from_folder(dir) fits + saves a bank from any folder of normal
       images — point it at AeBAD / MVTec "good" splits once those gated
       datasets are pulled.

3) AGENTIC COPILOT — NOW WORKS FULLY OFFLINE: src/l3_agent/copilot.py
   Previously ask() returned "(LLM offline)" with an EMPTY tool_trace whenever
   Ollama wasn't running — which hid the agentic behaviour in exactly the
   scenario (offline, airplane-mode Pi) this whole project is about. Added
   _offline_agent(): a deterministic tool-router that parses the question's
   intent + entities (defect type, ATA zone, mm sizes, tail number) with
   regex, and ACTUALLY CALLS the real twin tools (get_srm_limit / get_rul /
   get_tail_state), returning a genuine answer with a populated tool_trace —
   not a canned string. Honestly labelled in the UI as "deterministic
   tool-router — start Ollama for free-form prose" so nobody mistakes it for
   an LLM. Verified live against the running API:
     POST /api/ask?question="state of VT-AXB"
       -> "VT-AXB: health 33/100, 1 open defect(s). PULL INSPECTION FORWARD
           3800 cycles - defect growth outruns the 6000-cycle calendar
           interval" with tool_trace=[get_tail_state(...)]
     POST /api/ask?question="RUL for an 8 mm crack, 12 mm limit"
       -> real Monte-Carlo P10/P50/P90 numbers, tool_trace=[get_rul(...)]
   copilot.py's own _demo() self-check still passes (guardrail still escalates
   work orders that have no SRM citation, with or without an LLM).
